# 记忆日记（astrbot_plugin_memory_diary）

让 AstrBot 连接的 AI 在收到指令时，给"下一个失去记忆的自己"写一篇日记；
开启新上下文（`/reset`）后，第一句正常对话时她会自动先读**最近 7 天**的日记（范围可调），不再脑袋空空。

内置**上下文哨兵**：每次请求前估算上下文 token 占用，快满时主动提醒你，再满一点她会自己把日记写好，叫你去 `/reset`。

> 当前插件版本 **v0.5.0**；日记数据格式为“按天归档 v3”。插件版本和数据格式版本不是同一个东西，升级时旧格式会自动迁移。

> ✨ **v0.5.0 新增「每天定时自动写完整日记」**：配置页打开开关并设定一个时间（默认 22:00，按「日记时区」），
> 到点给有过私聊会话的用户自动写一篇完整日记；当天已有完整日记、没有新素材会跳过；每个用户每天只尝试一次、
> 失败不重试；写完后按人设口吻主动私聊告知。详见下方「每天定时自动写完整日记」。

> ✨ **v0.4.1 变更**：开启「按人设口吻」后，**几乎所有指令的对话式反馈**都改用当前会话人设的口吻输出——
> 写日记与写完告知、备忘/查看日记/删除日记的确认/拒绝/取消/超时、导出/导入日记的流程反馈、
> 查看密码的操作反馈、注入范围设置与注入确认、上下文哨兵的提醒与自动写完告知。
> 列表、日期清单、帮助菜单、日记状态、日记正文以及保存失败/验签/密钥等技术报错仍然保持固定文案；
> 关闭开关时全部是固定文案，人设生成失败也会自动回退固定文案。

> 📦 **v0.4.0 起，云端服务器取日记不再需要 SSH**：私聊发 `/导出日记`，插件会把日记和**只属于你的签名钥匙**
> 打包成迁移包，通过 QQ 私聊文件直接发给你；新设备上发 `/导入日记` 并把迁移包发回给她即可自动完成迁移
> （逐篇验签通过才安放）。签名钥匙按 QQ 从主密钥派生，泄露也只能动你这一份日记，主密钥永不出服务器。
> 手动 SSH 取文件的方式仍然保留，详见"日记存储位置与提取"。

## 按天归档（数据格式 v3）

- 日记**按天归档，一天一个文件**：当天写多篇会追加在同一天的文件里，用时间分隔条隔开，
  不会出现"一天几十篇"的碎片化
- 每次写日记记录的是"上一篇日记到现在"这段时间的事，不做全文合并——
  日记体积随时间可控，不会因为越攒越大而吃爆上下文
- 新上下文默认自动注入**最近 7 天**的文件（可在配置改天数、0 为全部，用户也可用 `/日记范围` 自己覆盖）；更早的日期不主动读取，但随时可以查

## 三种写作模式（省 token 设计）

| 模式 | 触发条件 | 写什么 |
| --- | --- | --- |
| 完整日记 | `/日记 完整`；第一次写日记；哨兵到 90% 自动写；或每天定时自动写（配置开启） | 完整的四部分日记（见下），作为跨会话质量锚点。会把**同一场景**之前未吸收的简记作为素材合并 |
| 当天简记 | 默认 `/日记`；`/日记 简记`；或完整篇名额已满时的自动降级 | 只用 1~3 句简略概括新增内容，不占完整篇名额，追加在当天文件里 |
| 她的日常随笔 | 距上次写日记**一句话也没聊过** | 不编造用户言行，改写她（AI）自己的拟人生活：看到了什么、做了什么、想了什么；带"无新对话·她的日常随笔"标注。可在配置"无新素材时写拟人日常"关闭 |

**“完整”不是“当天第一篇”的同义词，而是“质量锚点”**：

- 默认命令先写简记，不浪费素材；
- 用户觉得这段时间重要，发 `/日记 完整`；
- 第一次写日记默认完整，给新用户一个初始锚点；
- 自动哨兵在 90% 时写完整；每天定时自动写也会写完整（当天已有完整篇则跳过）；
- 完整篇写完后再写简记，简记不会反向合并进完整篇。

完整篇会吸收同一场景之前的简记：旧简记原文保留，但分隔条会标记“（已吸收）”，注入时跳过，不会重复占 token。跨场景暂不合并：私聊吸收私聊，群聊只吸收群聊（当前群与群仍算同一个场景，不按具体群隔离）。

判断“有没有新内容”现在靠**素材游标**（记录上次写到哪里），不是整段素材哈希：下次只读游标之后的新消息，避免多篇日记反复读同一段历史。游标失效（reset、历史被压缩）时回退最近 N 条，并在写作提示里注明可能重叠。

哨兵**自动写**不会触发“日常随笔”——没新素材时不写日记，但会明确提醒你“上下文快满了、这轮没新内容、建议 /reset”，绝不静默。

## 日记包含什么

每篇**完整日记**固定包含四个部分：

1. **涵盖时间** —— 这篇记录覆盖的起止时间
2. **用户画像** —— 这段时间新了解到的称呼、性格、偏好、习惯、在意的东西（基于对话事实）
3. **我对用户的看法与评价** —— AI 第一人称的真实印象与感受
4. **给未来的我的叮嘱** —— 延续什么、注意什么、避免什么

四个部分之间会自然穿插她自己的"私人生活"片段——心情变化、等待你回复时的小思绪、
灵光一闪的想法、想吐槽的瞬间——像人类日记一样有"人味"。
但涉及你的事实与画像永远基于真实对话，不编造。

## 使用方法

| 指令 | 作用 |
| --- | --- |
| `/日记`（或 `/diary`、`/写日记`） | 默认写一篇**简记**；第一次写日记会写完整篇。写完用平时的口吻告诉你一声（默认不展示全文） |
| `/日记 完整`（或 `/写日记 完整`） | 写一篇完整日记，并把**同场景**之前未吸收的简记作为素材合并；旧简记标记“已吸收”，注入时跳过 |
| `/日记 简记`（或 `/写日记 简记`） | 强制只写一段简记，不占完整篇名额 |
| `/记一下 要记住的事`（或 `/memo`、`/记住`） | 把一件重要的事存为备忘（指令和内容在同一句话里、空格分开），下次写日记时作为"用户特别叮嘱"重点写进画像；写入后自动清除。**备忘带场景标签：私聊写日记吸收全部备忘，群聊写日记只吸收群聊备忘**（私聊备忘不会借道群聊日记泄露）；两个场景各存 20 条、互不占额度 |
| `/查看备忘`（或 `/memo_view`） | 仅私聊。列出全部待写入的备忘（带时间和场景标注） |
| `/删除备忘`（或 `/memo_delete`） | 仅私聊。先列出备忘，回复序号删一条、回复「全部」清空，60 秒内有效，回复「取消」退出；备忘可以再记，无需二次确认 |
| `/查看日记` | 仅私聊。先列出全部日记日期，然后按提示回复：「最新」/ 序号 / 日期（如 `2026-10-23`），60 秒内有效，回复「取消」退出；查的日期没有日记会如实告知 |
| `/删除日记` | 仅私聊。先列出日期，再选：「全部」（需二次确认）/ 序号 / 日期 / 时间段（如 `2026-10-20 到 2026-10-23`），60 秒内有效，回复「取消」退出 |
| `/导出日记`（或 `/diary_export`） | 仅私聊，人人都可导出自己的日记：把**你日记文件里的全部篇目**（所有天，含完整/简记/随笔与同日追加段；不受 `/日记范围` 影响，也不含备忘和面板设置）+ 你的派生签名钥匙打包成迁移包，通过 QQ 私聊文件直接发给你——云端服务器取日记免 SSH。只按发起指令的 QQ 号取文件、只发给本人；钥匙只动得了你这份日记，但仍请勿转发他人 |
| `/导入日记`（或 `/diary_import`） | 仅私聊，导入自己的迁移包。把迁移包当 QQ 文件发给她：先全量验签确认包没被改过，再用本机钥匙重签安放（源设备钥匙与本机一致时签名原样有效），本机其他日记不受影响。120 秒内有效，回复「取消」退出 |
| `/日记状态` | 查看上下文占用、日记篇数与最新篇时间、哨兵状态 |
| `/日记密码`（或 `/diary_password`） | 仅私聊。给 Web「日记本」页面加查看密码：`/日记密码 设置 新密码` / `修改 旧密码 新密码` / `取消 旧密码`；无参数查看当前是否已设置。设锁后面板上翻阅和导出你的日记都要先输密码（只防面板翻看，防不了服务器文件权限） |
| `/日记范围` | 设置新上下文注入哪些日记：`最新`（只读最新一天）/ `全部` / `最近7天` / `2026-10-01到2026-10-23`（带空格写成 `2026-10-01 到 2026-10-23` 也可以）/ `默认`（恢复管理员配置）；无参数查看当前设置。未设置时按配置的"默认注入最近几天的日记"（出厂 7 天）注入 |
| `/注入日记 范围`（或 `/diary_inject`） | 主动让她现在就读指定日记：`最新` / `全部` / `最近N天` / 单日 `2026-10-23` / 时间段。下一句正常对话时生效，临时一次性带入；**本会话已注入过的篇目自动去重不重复读** |
| `/日记帮助`（或 `/diary_help`） | 查看全部指令与用法；群里被@点名时才响应，不抢话 |

## 标准使用流程（SOP）

**第一步：部署与初始化（管理员，只做一次）**

1. 安装插件并在 WebUI 重载（见下方"安装"一节）；
2. 把"模型上下文窗口"填成你实际模型的上限（如 DeepSeek-V3 填 60000），
   并确认 AstrBot 的"最大上下文消息数"没有设得太小——否则历史会在到达阈值前被 AstrBot 自己截断，哨兵就失效了；
3. 按需调整阈值与间隔（默认值适合大多数场景，可以先不动）；
4. 如果群里有多个 AI 都装了本插件：给每个实例填"我的称呼"，并建议全部开启"群里只响应@我的指令"。

**第二步：日常使用（用户，一个记忆周期）**

1. **正常聊天**，什么都不用管——哨兵在后台静默估算上下文占用；
2. 聊天中想到什么必须记住的事，随时发 `/记一下 内容`，她会存成备忘；
3. 上下文用到约 75% 时，她会提醒一次"快到写日记的时候啦"——这是信号：**把还没说的重要事说完**；
4. 用到约 90% 时她会自动写好**完整日记**（也可以随时主动发 `/日记` 写简记；觉得重要就发 `/日记 完整`），写完用平时的口吻告诉你一声；
5. 发 `/reset` 开启新上下文——她会先自动读最近 7 天的日记，再接着陪你，记忆无缝衔接
   （注入发生在 reset 后第一句正常对话时；命令消息不触发也不妨碍注入，
   不确定有没有注入成功可以发 `/日记状态` 看"本会话日记注入"一栏）；
6. 回到第 1 步，开始下一个周期。

**第三步：查看与维护（按需）**

- 用户：私聊 `/查看日记` 看自己的日记，私聊 `/删除日记` 清理，`/日记范围` 调整每次注入多少，`/日记状态` 看占用与篇数；
- 管理员：定期备份插件数据目录（**必须包含 `.diary_key`**，否则全部日记验签失效）；
  用户换设备取日记让他自己发 `/导出日记` 即可（QQ 直发、含本人派生签名钥匙、可跨设备迁移）；
  手动发文件时只发对应的 `diary_<哈希>.zip`，主密钥不要外传（详见"日记存储位置与提取"）。

## 上下文哨兵（自动提醒）

- 占用 ≥ **提醒阈值**（默认 75%）：提醒一次"快到写日记的时候啦"
- 占用 ≥ **自动写日记阈值**（默认 90%）：自动写一篇新日记（用她的口吻告知你，不贴全文），并提醒 `/reset`
- 每个会话各触发一次，`/reset` 后重新计数；token 数为按字符数的粗略估算（约 1 token ≈ 1.8 字符）

> 注意：请在配置里把"模型上下文窗口"设成你实际模型的上限（如 DeepSeek-V3 填 60000），
> 并确认 AstrBot 的"最大上下文消息数"没有设得太小，否则历史可能在到阈值前就被 AstrBot 自己截断。
> 提醒阈值必须 ≤ 自动写日记阈值；配置颠倒时插件会自动截断提醒阈值并记日志，不会报错崩溃。

## 每天定时自动写完整日记（v0.5.0）

在配置页打开「每天定时自动写完整日记」并填一个时间（`auto_diary_time`，默认 `22:00`，按「日记时区」计算），
插件会在每天到点时，给**有过私聊会话的用户**自动写一篇**完整日记**（等同 `/写日记 完整`）：

- **当天已写过完整日记就跳过**：只要当天已有任意完整篇（私聊或群聊场景都算），到点不再写；
- **没有新素材就不写**：距上次写日记没有新聊天、也没有当天未吸收的简记时，静默跳过
  （不会写“日常随笔”，也不打扰用户）；
- **每个用户每天只尝试一次，失败不重试**：写完会按人设口吻主动私聊告知
  （配置「按人设口吻」关闭时用固定文案）；写入失败只发一次固定技术说明，让用户知道可以手动 `/日记`；
- **只对私聊用户生效**：写和通知都走私聊，群聊会话不参与。用户表会在插件启动时从 AstrBot 现有私聊会话补齐，
  之后每次私聊消息也会自动登记；从没和 bot 私聊过的用户不会收到自动日记；
- **错过不补写**：到点时 bot 必须在线；启动/重启比设定时间晚 **2 分钟以内**会补触发一次，超过就当今天错过、等明天；
- 自动写与手动 `/日记` 共用素材游标、备忘吸收、完整篇名额等规则；它不占用“日记操作间隔”，
  也不受「手动写日记的最低上下文占用」门槛限制，不需要 `/reset`；
- **成本提示**：到点会给每个登记用户各尝试一篇完整日记——有素材的用户会调用一次模型写日记；若「按人设口吻」开启，成功/失败通知还会各多一次调用。用户多的实例请评估 token 消耗；没有新素材的用户会在调用模型前跳过。

## 日记本可视化页面（v0.4.0）

在 AstrBot 管理面板的插件详情页里多了一个**「日记本」视图**（活页日记本样式）：

- **翻阅日记**：左页是按天归档的目录，右页是日记正文，点目录或按 ←/→ 方向键翻页；
  验签失败的篇目会明确标注、拒绝展示；
- **导出日记**：选中用户后一键导出迁移包（日记 + 该主人的派生签名钥匙），两种方式：
  「下载到浏览器」走浏览器下载；「存到本机并打开位置」直接存进本机「下载」文件夹
  并自动打开文件管理器选中文件（仅当管理面板就开在服务器本机时可用）；
  与 `/导出日记` 指令等效；
- **导入日记**：上传迁移包，全量验签通过后自动安放（本机已有其他密钥时自动重签共存），
  与 `/导入日记` 指令等效；
- 页面运行在管理面板的受限 iframe 里，**继承面板登录鉴权**——
  能打开管理面板的人才能看到，无需额外口令；
- 旧版 zip 的说明里没有主人 QQ（文件名是加密的、反推不出）：第一次翻开时会请你
  输入一次主人 QQ，全量验签通过后记住，以后免输；新写的日记 zip 已内置该信息，无需输入。
- 顶栏 **A− / A+** 调字号（13~22px）、**字体按钮**在楷体/宋体/黑体间切换；
  偏好按管理面板账号保存在服务器上，刷新和换浏览器都记得；
- **自定义纸张与背景板**：顶栏「纸张」换书页纸纹、「背景板」换书本背后的整张底衬，
  各自上传一张图片（PNG/JPG/WebP，≤3MB）或一键换回默认，互不影响；
  图片只存在服务器插件数据目录，所有面板账号共用；
- **页面称呼**：配置项「日记本页面的称呼」（`web_diary_brand`）决定左上角标题，
  显示为「XX的日记本」，默认 TA，最长 12 个字符；
- **查看密码**：日记主人可在 QQ 私聊发 `/日记密码 设置 新密码` 给 Web 页面加锁
  （`/日记密码 修改 旧 新`、`/日记密码 取消 旧`）；设锁后翻阅和导出都要先输密码，
  密码只存 PBKDF2 哈希、明文不落盘。
  注意：这层锁**只防管理面板里的随手翻看**——服务器文件系统的日记 zip
  本身仍能被拿到文件的人读取，它替代不了磁盘加密。

> 视图需要支持"插件可视化视图"的 AstrBot 版本；旧版本会自动降级（没有页面入口），
> 插件其余功能不受影响。

## 日记存储位置与提取（管理员向）

> **v0.4.0 起优先用插件内导出**：私聊发 `/导出日记`，日记 zip + 本人派生签名钥匙打包成迁移包经 QQ 私聊直发；
> 新设备发 `/导入日记` 并把迁移包发回即可自动完成迁移。以下手动方式仍然有效，适合运维排查。

插件用的是 **AstrBot 的插件数据目录**，不是插件安装目录。实际路径是：

```text
<AstrBot 数据根>/plugin_data/astrbot_plugin_memory_diary/
```

“数据根”按部署方式不同：

| 部署方式 | AstrBot 数据根 |
| --- | --- |
| 设置了 `ASTRBOT_ROOT` | `$ASTRBOT_ROOT/data` |
| AstrBot 桌面客户端 | `~/.astrbot/data` |
| **AstrBot Launcher（Windows）** | `~/.astrbot_launcher/instances/<实例UUID>/core/data` |
| 源码 / Docker | 启动时工作目录下的 `data` |

Windows Launcher 的实际例子：

```text
C:\Users\<用户名>\.astrbot_launcher\instances\<实例UUID>\core\data\plugin_data\astrbot_plugin_memory_diary
```

注意这里是 `instances\<UUID>\core\data`，不是 `C:\Users\<用户名>\.astrbot\data`，也不是 AstrBot 安装目录下的 `data`。

**Windows 一键定位并打开（推荐）**

不记得路径、不想一层层翻目录时，把下面这段**整体复制粘贴到 PowerShell 窗口**，回车等几秒：
它会递归搜索当前用户目录下所有 `diary_*.zip`，取最近修改的一个，把完整路径复制到剪贴板，并直接打开所在文件夹：

```powershell
$f = Get-ChildItem "$env:USERPROFILE" -Recurse -Filter "diary_*.zip" -ErrorAction SilentlyContinue |
     Sort-Object LastWriteTime -Descending |
     Select-Object -First 1

if ($f) {
    $f.FullName | Set-Clipboard
    Write-Host "已复制完整路径：" $f.FullName
    explorer $f.DirectoryName
} else {
    Write-Host "没找到 diary_*.zip：可能不是 Windows Launcher 部署，或 AstrBot 不在当前用户目录下。"
}
```

- 普通 Launcher 单实例用户：用这段就够了，打开的文件夹里 `diary_*.zip`、`.diary_key` 都在；
- **多用户/多实例**：它定位的是"最近写过日记"的那个实例目录；想精确定位某个实例，先按下方"Launcher 的实例 UUID 怎么查"确认 UUID 再走精确路径；
- `.corrupt-<时间戳>.zip` 损坏备份也符合 `diary_*.zip` 命名，可能排在最前——打开文件夹后注意辨认；
- **Docker / Linux 云端**：这段 Windows 命令不适用，用下文的 `docker exec` / `find`。

**Launcher 的实例 UUID 怎么查？**

Launcher 的每个实例就是 `instances` 下的一个文件夹，文件夹名就是 UUID：

```powershell
Get-ChildItem "$env:USERPROFILE\.astrbot_launcher\instances" -Directory |
    Select-Object Name, LastWriteTime
```

如果分不清哪个是正在用的实例，可以看正在运行的 AstrBot 进程路径，里面会带实例 UUID：

```powershell
Get-CimInstance Win32_Process |
    Where-Object { $_.ExecutablePath -like "*\.astrbot_launcher\instances\*" } |
    Select-Object -ExpandProperty ExecutablePath
```

路径里的 `instances\<这一串>\venv\...` 就是实例 UUID。只有一个实例文件夹时，直接用那个即可；Launcher 界面如果显示了实例 ID，也可以直接对照。

**找不到 zip 时，先确认它是“还没写”还是“找错目录”：**

- zip 是第一次成功写日记后才创建的。目录里只有 `.diary_key`、没有 `diary_*.zip`，可能是还没写成功，不一定是路径错。
- 文件名是 `diary_<16位哈希>.zip`，一个用户一个，不叫 `日记.zip`。
- `.diary_key` 是隐藏文件；`说明.txt` 在 zip 里面，不在目录根下。

Docker：

```bash
docker exec -it <容器名> sh -lc 'find / -type d -name astrbot_plugin_memory_diary 2>/dev/null'
```

Linux 源码部署：

```bash
find /root /opt /home /AstrBot /app -type d -name astrbot_plugin_memory_diary 2>/dev/null
```

目录结构：

```
├── .diary_key                  ← HMAC 主密钥（随机生成，各用户签名钥匙由它派生；留在 zip 外，备份/迁移务必带上）
├── diary_<用户ID哈希>.zip      ← 每个用户一个 zip，按天归档、分文件夹
│     ├── diaries/20261023.md   某一天的日记（当天多篇追加在同一文件，带时间分隔）
│     ├── sigs/20261023.sig     当天日记的防篡改签名（仅插件验签用，用户可忽略）
│     ├── diaries/20261024.md   又一天……
│     └── 说明.txt              日记结构、使用方法、存储位置
├── auto_diary_users.json       ← 每天定时自动写日记的私聊用户登记（QQ/UMO/昵称，仅用于写与主动通知）
├── auto_diary_state.json       ← 每天定时自动写日记当天是否已触发（防重复/失败不重试）
```

**提取事项：**

- **跨设备迁移（换电脑/换服务器）**：用 `/导出日记` + `/导入日记`，全程 QQ 内完成，签名原样通过，不用碰以下任何手动步骤。
- 想手动把日记发给某位用户**阅读**（不迁移插件数据）：直接把对应的 `diary_<哈希>.zip` 发过去即可，对方解压后挑需要的 `.md` 读，按 `说明.txt` 的指引可以喂给任何设备上的任何 AI。
- **手动发阅读用 zip 时不需要 `.diary_key`**：主密钥只用于插件验签和备份迁移，阅读和第三方 AI 都用不到它；zip 未加密，任何人拿到都能读——发送前请确认对象确实是日记主人。
- **手动迁移插件数据时则必须带上 `.diary_key`**：日记文件名和每篇签名都由它派生，少了它新设备找不到文件、验签全部失败。v0.4.0 起也接受把密钥文本存为 `diary_key.txt` 放进数据目录，插件启动时会自动收养为 `.diary_key`（仅当本机还没有密钥时）。
- 插件读写 zip 对模型完全透明，zip 存储不影响任何 AI 功能。
- **不要手改 zip 里的任何 .md**：验签会失败，插件将拒绝读取该篇（这是防篡改设计，不是故障）。
- 备份/迁移整个插件目录时必须包含 `.diary_key`，否则所有日记验签失效。
- 文件名是发送者 ID（如 QQ 号）经 `.diary_key` 做 HMAC 派生的哈希前 16 位（v0.3.0 起；旧版 MD5 命名的文件会在首次访问时自动改名迁移）。**只拿到 zip、没有拿到 `.diary_key` 时**，无法靠枚举 QQ 号定位文件；如果整个数据目录连同 `.diary_key` 一起泄露，仍可计算文件名并验签——所以目录权限和密钥备份都要保护。可让对应用户发 `/日记状态` 核对，或按 zip 内 `说明.txt` 的昵称辨认。
- v1.x 明文 `.md + .sig`、v2.0 单篇 zip、v3.0 按篇时间戳条目、v3.1~3.3 平铺按天文件，都会在首次读取时自动迁移为 `diaries/` + `sigs/` 分文件夹的按天归档（同一天的多篇合并、保留时间分隔条）。

## 安装

- **源码 / Docker 部署**：将整个 `astrbot_plugin_memory_diary` 文件夹放入 AstrBot 的 `data/plugins/` 目录；
- **AstrBot Launcher（Windows）**：放入对应实例的 `...\instances\<实例UUID>\core\data\plugins\`；
- 也可以在 WebUI 插件页直接上传 `astrbot_plugin_memory_diary.zip` 安装。

放好后在 WebUI 插件页重载即可。

> **部署方式建议**：本地部署（Windows 桌面客户端 / Launcher / 本机源码）和云端部署均可；
> 云端取日记请用 `/导出日记`，无需 SSH。

> **云端 / Docker 部署注意**：
> - `/导出日记` 的 QQ 文件直发，依赖协议端（NapCat）能读到 AstrBot 数据目录里的临时迁移包。
>   同机、同容器或**共享卷**部署可以直接用；如果 AstrBot 与 NapCat 分属两个**没有共享卷**的容器，
>   会提示“包打好了但发送失败（协议端可能读不到这个文件路径）”——给两个容器挂同一个数据卷
>   （挂到相同路径），或改用管理面板「日记本」页的导出（浏览器下载，不依赖协议端读文件）。
> - `/导入日记` 不受共享卷限制：文件由 QQ 协议端上传、AstrBot 侧下载到本地临时文件后验签安放。
> - 换云端服务器：新实例装好插件并**启动一次**（让本机生成自己的 `.diary_key`），再让用户发
>   `/导入日记`；两边主密钥不同时会自动重签共存（resign），不影响新服务器上其他用户的日记。
>   如果直接搬整个插件数据目录，则必须连 `.diary_key` 一起带（见"日记存储位置与提取"）。
> - 插件目前声明支持 `aiocqhttp`（NapCat 等）；其他协议端能否收发文件，取决于其 File 组件实现。


## 配置项（WebUI 插件配置面板）

- **新会话自动读取日记**：关闭后只写日记、不自动注入
- **启用上下文哨兵**：关闭后不估算、不提醒、不自动写（下面的上下文窗口、提醒阈值、自动写日记阈值三项均不生效）
- **模型上下文窗口（tokens）**：默认 60000，按你的模型实际上限填；仅在启用上下文哨兵后生效
- **提醒阈值 / 自动写日记阈值**：默认 0.75 / 0.9，配置页为滑块（0.1~1.0）。仅在启用上下文哨兵后生效；要求提醒阈值 ≤ 自动写日记阈值，配置颠倒时插件自动截断提醒阈值并记日志
- **默认注入最近几天的日记**：默认 7 天；0 表示注入全部。用户可用 `/日记范围` 自己覆盖
- **注入持久化**：默认关闭。关闭时日记只在每个新会话的第一轮请求注入一次（省 token，但她只在生成第一条回复时记得日记细节）；开启后每轮请求都把日记放进 system prompt，她全程都能回忆日记内容，代价是每轮都消耗日记的 token（约 字数 ÷ 1.8）
- **注入日记的最大字符数**：默认 8000。防炸上下文保险丝——即使用户要求注入全部日记，总量超过该值也会优先保留最近的、截断更旧的并在注入文本中注明
- **群聊注入过滤**：默认开启。在群聊的新上下文中只注入"写于群聊"的日记片段，私聊写下的片段不进群聊；反向不限（群聊片段在私聊照常注入）。无场景标记的旧日记片段视为私聊来源、不注入群聊。某天若全是私聊片段，该天整天跳过并在注入文本中注明
- **日记操作间隔（分钟）**：默认 5，每个用户两次写日记/删日记的最小间隔；0 为不限制，最高 60。查看和哨兵自动写日记不受限
- **手动写日记的最低上下文占用**：默认 0（不限制）。设成如 0.5 后，上下文占用未过半时 `/日记` 会被婉拒；哨兵自动写日记不受此限
- **每个场景每天最多几篇完整日记**：默认 1；0 表示不限制（适合 token 充足、希望多写完整篇的用户）。按场景计算：私聊和群聊各自独立（群与群目前不隔离），简记不占额度
- **每天定时自动写完整日记**：默认关闭。开启后每天到「自动写日记时间」，给有过私聊会话的用户自动写一篇完整日记；当天已写过完整日记（私聊或群聊都算）或没有新素材时跳过；每个用户每天只尝试一次，失败不重试。详见「每天定时自动写完整日记」
- **自动写日记时间**：默认 22:00，24 小时制 `HH:MM`，按「日记时区」计算；仅开启上一项后生效。格式不对时不会自动写并记日志；bot 启动/重启晚于该时间超过 2 分钟不补写
- **写日记时读取的最大消息条数**：默认 60。有素材游标时只读“上次写日记之后”的全部新消息；游标失效（reset/历史压缩）时才回退最近 N 条。条数与写日记时**一次性**消耗的 token 成正比，但量不大
- **群聊素材倍率**：默认 3。群聊历史混有其他成员发言（且历史不带发送者 ID、无法按人过滤），游标失效回退时实际读取 = 最大条数 × 倍率，提高覆盖到画像对象本人发言的概率；私聊不受影响
- **按人设口吻**：默认开启，读取当前会话的人设（含 `/persona` 切换的人设），**尽可能多的指令反馈都改用她的性格与口吻输出**：写日记与写完后的口头告知；`/记一下` 的记下确认；备忘、查看日记、删除日记的确认/拒绝/取消/超时反馈；`/导出日记` 与 `/导入日记` 的打包、发送、取消、没收到文件、导入成功/被拒绝/超时等流程反馈；`/日记密码` 的设置/修改/取消结果与各类拒绝；`/日记范围` 设置成功的确认；`/注入日记` 的注入确认与"本会话已读过"告知；上下文哨兵的提醒与自动写完告知；每天定时自动写日记的写完告知。**列表、日期清单、帮助菜单、日记状态、日记正文，以及保存失败/验签失败/密钥不可用等技术报错保持固定文案**（保证数字、日期、指令与诊断信息逐字准确）；关闭后全部使用固定文案。完整清单见下方「按人设口吻的覆盖范围与边界」
- **无新素材时写拟人日常**：默认开启。用户要求写日记但距上次没有任何新对话时，她会写一段自己的拟人生活随笔（明确标注、不含用户画像）；关闭后直接提示没有新内容、不写
- **写完后展示日记全文**：默认关闭，她只用正常口吻告知日记已写好；开启后会在告知后附上全文（仅私聊生效）
- **写日记的附加要求**：自定义追加到写作提示词的要求（如语气、格式偏好）
- **日记时区**：默认 Asia/Shanghai。写日记的时间戳、按天归档、"最近 N 天"的计算都用这个时区；填 IANA 时区名（如 `Asia/Tokyo`），留空跟随服务器本地时间，填错会回退本地并记日志
- **我的称呼（多 AI 防冲突）**：群里装了本插件的 AI 不止一个时必配。填这个 AI 的名字，多个名字用英文逗号或中文逗号分隔都可以（如 `小深,DeepSeek` 或 `小深，深深`）
- **群里只响应@我的指令**：默认关闭。开启后群里不带@的日记指令一律无视，彻底杜绝多 AI 抢答
- **日记本页面的称呼**：默认 TA。管理面板「日记本」视图左上角显示为「XX的日记本」，留空回退 TA，最长 12 个字符

## 按人设口吻的覆盖范围与边界

「按人设口吻」（配置项 `use_persona`，默认开启）会读取**当前会话**的人设（含用 `/persona` 切换的人设；会话没指定时回退到默认人格），
让模型把指令的**对话式反馈**用自己的性格与口吻重说一遍再发给你。每一处生成提示词都会明确要求
“必须保留”其中的数字、日期、条数与指令写法；模型写偏或不可用时，自动退回原来的固定文案。
目标是在不牺牲数据准确性的前提下，让她的口吻覆盖尽可能多的指令反馈。

### 一、全句人设化的场景（按指令分组）

| 指令 | 哪些反馈会用人设口吻 |
| --- | --- |
| `/日记`（写日记） | 写完后的口头告知；操作冷却的婉拒；上下文占用未达门槛的婉拒；没有新素材 / 今天的随笔已写过之类的对话式拒绝 |
| `/记一下`（写备忘） | 记下成功的确认（保留原话引用与待写条数；场景说明仍固定追加）；保存失败保持固定文案 |
| `/查看备忘` `/删除备忘` | 群聊拒绝；查看时没有待写入的备忘 / 删除时没有可删的备忘；删除一条 / 清空全部 / 取消 / 回复看不懂导致的取消（人设化告知已取消）/ 序号不存在（保留当前条数） |
| `/查看日记` | 群聊拒绝；还没有写过日记；取消查看；超时；所选日期没有日记；验签失败 / 被篡改的诊断提示保持固定文案；回复看不懂或序号越界时只给固定用法提示并**继续等待**（不取消、不人设化） |
| `/删除日记` | 群聊拒绝；还没有日记；操作冷却的婉拒；取消删除（含删除全部时在二次确认环节放弃）；删除成功（保留天数与日期列表）；全部删除完成；超时；日期或时间段合法但查不到日记（人设化告知后结束等待）；序号越界或回复看不懂时只给固定用法提示并**继续等待**（不人设化、不取消）；删除失败（权限 / IO）为固定文案 |
| `/导出日记` | 群聊拒绝；还没有日记可导出；打包完成告知（保留天数与钥匙提醒）；迁移包已发出告知 |
| `/导入日记` | 群聊拒绝；请把迁移包作为「文件」发来的提示（保留「文件」「120 秒」「取消」）；取消导入；没收到文件；文件下载失败；导入成功（保留天数与签名方式）；导入被拒绝（原因原样保留）；导入超时 |
| `/日记密码` | 群聊拒绝；设置 / 修改 / 取消的结果告知；已设置过、未设置过、旧密码不对、新密码不合规（保留 4~32 位、不含空格的要求）、本来没有密码却要取消、取消时密码不对等拒绝反馈（无参查看状态与用法、保存失败保持固定） |
| `/日记范围` | 设置成功的确认（保留范围描述与“下次 /reset 后生效”）；无参查看当前设置、“没看懂～可选…”用法提示、保存失败保持固定 |
| `/注入日记` | 还没有日记可注入；指定范围里没有日记（保留范围描述）；本会话都读过了、没有新篇目的告知；注入确认（保留日期清单）；无参用法与“没看懂”提示保持固定（本指令无等待式交互） |
| 上下文哨兵 | 占用达到提醒阈值时的提醒；上下文将满但本轮没有新素材可写的警告（都保留百分比、`used/limit` tokens 与 `/reset`、`/日记` 等指令写法）；自动写日记完成后的告知（`used/limit` 的提示行保持固定格式，告知正文用人设口吻） |
| 每天定时自动写日记 | 写完后主动私聊的人设口吻告知；写入失败时只发一次固定技术说明（不重试，保留原因与 `/日记` 指引） |

> 人设化只改**措辞**，不改判定：冷却、门槛、权限、删除与注入逻辑仍按固定规则执行，
> 反馈里的事实由插件在提示词中给定，不是让模型自行回忆。

### 二、只用固定文案 / 固定正文的场景

| 场景 | 具体内容 | 为什么保持固定 |
| --- | --- | --- |
| 列表与数据 | 日记日期清单、备忘清单、`/日记状态` 的数字、帮助菜单、无参数时的设置与用法（`/日记密码` 的状态、`/日记范围` 的当前设置与用法、`/注入日记` 的用法）、用法示例与“没看懂～…”指引 | 数字、日期、指令语法必须逐字准确，转述容易漏项或改错格式 |
| 日记正文 | `/查看日记` 读出的日记全文、写完后展示的全文、注入给模型的日记内容、导出包里的日记 | 日记原文必须原样，不能被二次创作或摘要 |
| 技术 / 安全诊断 | 密钥不可读、验签失败、zip 损坏、保存失败 / 权限失败、导出文件发送失败、自动写日记失败、导入 / 导出的兜底失败提示、`_write_diary` 返回的技术性错误、环境不支持交互 | 诊断信息是排查线索，必须以固定措辞、原样原因给出，不能让模型“友好化”后失真 |
| 安全提示 | 删除全部日记的二次确认 | 二次确认是安全闸门，措辞必须固定、明确，不能被改写弱化 |
| 保存失败告知 | `/记一下`、`/日记密码`、`/日记范围` 的保存失败（数据目录不可写或磁盘已满） | 必须明确“没有改动”，不能让口吻化掩盖写入失败 |

### 三、开关关闭与生成失败时的回退

- **关闭「按人设口吻」**（`use_persona=false`）：所有指令反馈直接使用固定文案，**不会额外调用 LLM**
  （不增加 token 消耗，也不增加响应延迟），输出与未开启时逐字一致。
- **开启但本次生成失败**：没有可用模型、调用报错、返回空，或当前会话与默认人格都取不到人设文案时，
  自动回退到同一处的固定文案——指令照常完成，不会因为模型抽风而失败。
- **回退只影响措辞**：无论走人设还是固定文案，删除、保存、注入等结果完全一致；
  数字、日期、指令与技术诊断在两种路径下都保持准确。

## 群里有两个以上 AI 都装了本插件？（防冲突）

指令支持**广义**和**点名**两种写法，可同时使用：

| 写法 | 效果 |
| --- | --- |
| `/写日记` | 广义指令：所有装插件的 AI 都会响应（适合只有一个 AI 的群） |
| `/写日记@小深`（连写）或 QQ 自带@ | 点名指令：只有"小深"响应，其他 AI 保持沉默 |

点名规则：

- @用 QQ 自带的@功能最可靠（按 QQ 号精确比对）；文本形式 `@名字` 也可以，但要**和指令连写**（`/写日记@小深`），并在配置"我的称呼"里填好这个 AI 的名字才能对上号
- 指令里 **@了别人**（其他 AI 或群友）时，她会判断"不是叫我"，完全不响应、不抢话
- 只有指令本体上的 @ 才算点名：**内容里的 @ 不会误判**——`/记一下 记得@张三 他下周考试` 里的 `@张三` 是要记的内容，她照常响应并记下
- 开启"群里只响应@我的指令"后，连不带@的广义指令也会无视——多 AI 群建议每个实例都开启（此时点名请用 QQ 自带@或连写形式）
- **带参数的指令**（`/日记 完整`、`/日记 简记`、`/日记范围`、`/注入日记`）在群里请用 **QQ 自带@** 点名；文本 `@名字` 只适用于 `/写日记@小深` 这种指令本体连写，参数里的文本 @ 不会被当作叫它
- 私聊不受任何限制，永远响应
- 注意：请把@放在指令后面，放在指令前面可能不会被识别为指令

## 多用户与隐私

- 日记按**用户**（发送者 ID）完全隔离：谁下指令写的就是谁的画像，各自保存、各自注入，互不影响。
- 群聊里写日记时，会在写作提示中声明"记录来自群聊、可能包含其他成员发言"，要求只围绕画像对象本人来写。
- `/查看日记` **仅私聊可用**，在群里使用会被拒绝，日记内容不会出现在群消息里。
- "写完后展示日记全文"只在私聊生效，群聊中即使开启也只口头告知、不展示全文。
- **注入按会话场景过滤（方向性）**：每个日记片段的分隔条都带"写于私聊 / 写于群聊"标注。在群聊的新上下文中只注入群聊来源的片段——私聊里的悄悄话不会顺着日记被带进群里；反过来，群聊来源的片段在私聊中照常注入（配置"群聊注入过滤"可关）。注意：这意味着她在群里可能"只知道群里的事"，表现会和私聊略有差异，这是设计使然。
- **群与群之间不隔离（设计边界，请知悉）**：隔离只分"私聊/群聊"两个场景，不区分具体哪个群。A 群写下的群聊日记片段，在你和 AI 同在的 B 群也可能被注入；A 群的群聊备忘也可能在 B 群写日记时被吸收。如果你和她在多个群里相处，请把"所有群聊"当成一个共享场景来理解。
- **备忘同样按场景隔离**：`/记一下` 存的备忘带场景标签，私聊写日记吸收全部备忘，群聊写日记只吸收群聊备忘（私聊备忘继续等待，不会出现在群聊来源的日记片段里）；无场景标记的旧备忘视为私聊来源。
- 每个用户只能查看 / 删除自己的日记，无法访问他人的。
- **`/导出日记` 只能导出自己的**：插件按发起指令的发送者 QQ 号派生并读取其专属日记文件，迁移包也只通过私聊文件发给该发送者；群里发会被拒绝；指令后面带 `@别人` 或其它参数会被忽略（不会用来指定别人的日记）；包内只有本人的派生钥匙，别的用户钥匙无法验证/伪造这份签名，转发给别人也会因“主人 QQ 不一致”被导入拒绝。**管理面板「日记本」页的导出是管理员权限**，可以导出任意用户的日记（该用户设了查看密码时需先输入密码）——这与 QQ 指令侧的“只能导出自己”不是同一权限层级。
- **定时自动写日记的用户表**：`auto_diary_users.json` 只保存私聊会话的发送者 ID、UMO 与昵称，仅用于到点写日记和主动通知；`auto_diary_state.json` 只保存当天是否已触发。两者都在插件数据目录，不进入日记 zip/迁移包，也不参与注入；停用功能后不需要可手动删除，插件下次启动会按已有私聊会话重新补齐。
- **日记防篡改**：每篇日记保存时生成 HMAC-SHA256 签名（绑定用户+篇目名+内容），读取时验签。签名钥匙一人一把，由主密钥 `.diary_key` 按 QQ 号派生（v0.4.0 起；此前直接用主密钥签名，旧日记读取时自动回退验签、下次写入自动升级）。任何在插件之外的修改都会被判定失效——不查看、不注入，只有她写的日记才会被使用。注意：**验签失败时插件会拒绝整次写入**（不会把被改过的内容重新签成"合法"），请先删除该篇或恢复备份；签名密钥 `.diary_key` 不可读时同样拒绝写入。

## 故障与恢复

- **`.corrupt-<时间戳>.zip` 文件**：插件发现日记 zip 损坏时，不会覆盖它，而是把原文件改名成这个备份并拒绝写入。原路径这时已经不存在了；请人工检查备份（可尝试用压缩软件修复），确认没有可恢复内容后直接删除该备份即可，下次写日记会新建。不要手改备份再放回，签名会失效。
- **"验签失败"提示**：日记文件在插件之外被手动修改过。想保留就先用 `/删除日记` 删掉那天或从备份恢复，否则她不会再读这篇，也不会在它基础上写新日记。
- **"签名密钥不可用"提示**：数据目录下的 `.diary_key` 丢失、为空或不可读。**先从未丢失的备份恢复，不要直接删掉让它重建**——v0.3.0 的文件名也由这个密钥派生，重建后旧的 `diary_*.zip` 会变成插件找不到的孤儿文件，而且签名全部失效。只有确认旧日记都不要了，才手动清理旧 zip 后重建。
- **写入是原子操作**：zip 和 `pref_*.json` 都是“临时文件 + `os.replace`”，任何时刻目标路径上要么是完整旧文件、要么是完整新文件；进程中途被杀不会留下半个目标文件。崩溃可能留下 `.tmp-<pid>` / `.tmp` 临时残骸，可以手动删。

## 注入的时机与效果（重要）

- **默认（临时模式）**：每个新会话的第一轮 LLM 请求注入一次，注入文本是临时消息、不进会话历史——
  所以她**只在生成第一条回复时**"记得"日记细节，后续轮次只剩她自己回复里带出来的印象。
  省 token，适合大多数场景。
- **注入持久化（配置开启）**：每轮请求都把日记放进 system prompt，她全程都能回忆日记内容；
  代价是每轮都消耗日记的 token（约 字数 ÷ 1.8）。在乎"她全程记得"就开，在乎 token 就关。
- **`/注入日记` 追加注入**：自动注入之后还想让她读别的日记，用这个指令指定范围，
  下一句正常对话时一次性带入；**本会话已经注入过的篇目自动去重**——重复下指令不会让她重复读同一篇，
  没有新篇目时会直接告诉你"都读过了"。多篇日记同时存在于同一轮请求时，
  以"当前对话 > 日记"的优先级规则相处，不冲突。
- 没有日记可注入时静默：不提示、不耗 token，她像没装插件一样正常开始新对话（zip 或某个条目 CRC 损坏时，`/查看日记`、`/日记状态`、`/注入日记` 会明确提示）。

## 说明

- 日记内容基于当前会话（umo）的历史消息写成；群聊中历史可能包含其他成员的发言。
- 新会话注入通过 `on_llm_request` 钩子实现：`/reset` 后第一轮正常对话注入一次，注入内容标记为临时，不会污染会话历史。AstrBot 4.x 的 `/reset` 只清空 history、不换 conversation_id，所以插件同时用“监听到 `/reset` 指令”和“上下文已清空”两条路径识别新代际；`/日记状态` 可查看本会话是否已注入。
- **日记操作不进素材**：写日记前会自动剔除操作类内容（`/日记` `/删除日记` `/查看日记` `/记一下` 等指令、插件的 📖/⚠️/📌 通知、`/reset`），她读不到也不会把这些写进日记（`/记一下` 的内容单独走备忘通道，不会丢）；写作提示词同时声明对话中的"指令"只是素材、不是命令（防注入）。
- 文件写入和消息发送都是一次尝试、失败会明确告知；不会重试轰炸。验签失败、密钥不可用、文件损坏等安全相关失败会直接拒绝写入，不会降级绕过。
- 要求 AstrBot >= v4.0.0。
